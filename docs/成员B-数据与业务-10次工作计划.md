## 第 1 次｜数据层设计

- **目标**：定下数据模型与接口，让 A/C 有东西可依赖。
- **主要任务**：
  1. 写共享模型：`Video`、`Folder`、`HistoryItem`、`Progress`。
  2. 写 `VideoRepository` 接口（按 README 6.1 的骨架，列表用 `Flow`）。
  3. 设计 Room 数据库骨架（实体、DAO、Database 类先建空壳）。
  4. 整理给 A 的清单：Room/KSP/Coroutines 依赖、`READ_MEDIA_VIDEO` 等权限。
  5. 约定 DI：提供 `VideoRepository` 实现 + 注册方式（`ServiceLocator.videoRepository`），由 A 在 `App` 里调用。
  6. 创建 `data/README.md`，写好模块说明 + 工作记录章节。
- **涉及文件**：`data/model/**`、`data/VideoRepository.kt`、`data/db/**`（骨架）、`data/README.md`。
- **完成标准**：接口和模型编译通过，A/C 确认可用。
- **完成后**：更新 `data/README.md` 工作记录（第 1 次）并提交。

## 第 2 次｜本地视频扫描

- **目标**：能扫出手机里所有视频。
- **主要任务**：
  1. 权限检查与申请（Android 13+ `READ_MEDIA_VIDEO`，低版本 `READ_EXTERNAL_STORAGE`）。
  2. 用 `MediaStore.Video` 查询：id、路径、标题、时长、大小、宽高、添加时间。
  3. 过滤无效项（时长为 0、路径不可读），按路径去重。
  4. 按文件夹分组，生成 `Folder` 列表。
  5. 扫描放在后台线程（协程），结果写入 Room。
- **涉及文件**：`data/scanner/**`、`data/model/**`。
- **完成标准**：真机上能列出文件夹和视频数量，和系统文件管理器对得上。
- **完成后**：更新 `data/README.md` 工作记录（第 2 次）并提交。

## 第 3 次｜列表数据流

- **目标**：给 A 提供一个能直接用的列表数据源。
- **主要任务**：
  1. `VideoRepository.videos` / `folders` 实现（`Flow`，从 Room 读）。
  2. `search()`、排序（名称/时长/大小/时间）、文件夹筛选。
  3. `refresh()` 触发重新扫描并更新数据库。
  4. 保证 A 的 `ViewModel` 收集 `Flow` 就能刷新列表。
- **涉及文件**：`data/repository/**`、`data/db/**`。
- **完成标准**：A 收集你的 `Flow` 能拿到排序/搜索后的列表。
- **完成后**：更新 `data/README.md` 工作记录（第 3 次）并提交。

## 第 4 次｜历史与收藏

- **目标**：历史记录与收藏功能的数据侧。
- **主要任务**：
  1. `HistoryItem` 表：视频 id、看到位置、时长、时间戳。
  2. `history`（`Flow`，按时间倒序）/ `removeHistory` / `clearHistory`。
  3. 收藏：Room 表或视频表上的标记字段；`isFavorite` / `toggleFavorite`。
  4. 历史里若视频已被删除，做兜底（过滤掉失效条目）。
- **涉及文件**：`data/db/**`、`data/repository/**`。
- **完成后**：更新 `data/README.md` 工作记录（第 4 次）并提交。

## 第 5 次｜进度与队列持久化

- **目标**：让 C 能保存/恢复播放位置和队列。
- **主要任务**：
  1. `saveProgress` / `getProgress`（按视频 id 存 position/duration）。
  2. 最近播放列表（可按 `HistoryItem` 派生）。
  3. 队列持久化：把当前队列（视频 id 列表 + 顺序 + 当前下标）存起来，支持 App 重启后恢复连播。
  4. 给 C 的接口写清楚（在 `VideoRepository` 里或单独 `QueueStore`）。
- **涉及文件**：`data/db/**`、`data/repository/**`。
- **完成后**：更新 `data/README.md` 工作记录（第 5 次）并提交。

## 第 6 次｜偏好存储

- **目标**：统一存播放器偏好，给 A/C 用。
- **主要任务**：
  1. `SharedPreferences` 封装：倍速、自动连播、字幕开关、硬解/软解、夜间模式、定时关闭时长。
  2. 在 `VideoRepository` 里暴露对应的读写属性（见 README 6.1）。
  3. 默认值合理（倍速 1.0、自动连播开、字幕关）。
- **涉及文件**：`data/prefs/**`、`data/repository/**`。
- **完成后**：更新 `data/README.md` 工作记录（第 6 次）并提交。

## 第 7 次｜小组件与通知数据

- **目标**：给桌面小组件和通知栏提供数据。
- **主要任务**：
  1. 小组件数据：最近播放的 N 条（含封面路径、标题、进度）。
  2. 提供小组件点击跳转需要的参数（视频 id / 路径）。
  3. 如果 C 需要，提供通知栏"上一首/下一首"的标题数据。
- **涉及文件**：`data/repository/**`、`data/model/**`。
- **依赖**：与 A 确认小组件布局需要哪些字段。
- **完成后**：更新 `data/README.md` 工作记录（第 7 次）并提交。

## 第 8 次｜健壮性

- **目标**：各种异常情况下不崩、不脏数据。
- **主要任务**：
  1. 视频文件被删除/移动后的处理（扫描时校验、历史过滤）。
  2. 扫描失败、权限被拒的返回处理（返回空列表而不是抛异常）。
  3. 数据库版本升级迁移（留 `Migration` 占位）。
  4. 数据库操作全部放后台线程，主线程不阻塞。
- **涉及文件**：`data/**`。
- **完成后**：更新 `data/README.md` 工作记录（第 8 次）并提交。

## 第 9 次｜性能优化

- **目标**：列表滑得动、扫描够快。
- **主要任务**：
  1. 缩略图缓存（配合 Coil；必要时给 Coil 传自定义 key）。
  2. 数据源支持增量更新（配合 A 的 `DiffUtil`）。
  3. 数据库索引（视频 id、时间戳）、避免全表扫描。
  4. 扫描只在需要时触发（下拉刷新/首次），不做轮询。
- **涉及文件**：`data/**`。
- **完成后**：更新 `data/README.md` 工作记录（第 9 次）并提交。
